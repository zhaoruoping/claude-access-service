Claude 使用方案

两种方式，独立并行。

方式一 · 共享环境：使用服务器上的账号与网络出口， 无需自备账号与代理。仅支持 Claude Code（命令行）。

方式二 · 协助订阅：以本人身份与支付方式开通订阅， 账号归本人所有。网页版、桌面端、Claude Code 均可使用。

方式一 · 共享环境仅 Claude Code

这不是 API 中转

形式上有相似之处——都是把请求发到一个中间端点——但性质不同。

API 中转站本方式
上游按量计费的 API 额度服务器上的 Claude Max 订阅账号
可用客户端任意仅 Claude Code
客户端自行配置提供安装命令，自动安装与更新
网络出口只提供一个地址出口在美国服务器，固定不变

「按官方 API 价折算」只是计价口径，用来把用量换算成可比较的金额， 并不表示上游走的是 API 计费。

适用范围

本方式提供的是 Claude Code 命令行的使用能力， 不包含网页版 claude.ai 与桌面端。需要网页版或桌面端的，见方式二。

账号与网络出口均在服务器侧，使用者无需自备 Claude 账号，也无需自备代理。

环境要求

不需要 Claude 账号，不需要代理，不需要配置环境变量。 另需 curl 与 Python 3.8 以上，多数系统已自带。

运行方式

一条命令装好客户端并配置完成：

curl -fsSL https://srv1890566.hstgr.cloud/install.sh | sh

随后运行 sharedcc-claude，Claude Code 在本机执行，读写本机文件； 仅模型请求经 HTTPS 发往服务器转发。

本机                                      服务器
────────                                 ────────
sharedcc-claude（本机运行，读写本机文件）
   └─ 模型请求 ───HTTPS───▶ 账号与网络出口 ──▶ 官方上游
  • 代码不出本机：Claude Code 在本机运行，读写的是本机文件。
  • 本机不持有账号凭据：Claude 账号的凭据仅存在于服务器，使用者侧不接触。
  • 直连：服务器有公网地址，客户端直接连接，无中间环节。

隔离与记账

  • 不保存对话内容：Claude Code 运行在本机，服务器只做两件事——转发模型请求、 记录 token 用量。账目的字段是固定白名单（时间、用户、模型、状态、token 数）， 请求与回复的正文不写入任何日志。
  • 账号凭据不外发：认证在服务器侧补齐，使用者侧接触不到 Claude 账号的凭据。
  • 用量逐条记录：每次请求的模型与 token 消耗均有记录，账目可查、可核对。
  • 按 key 归属：每次请求归属到本人的 key，账目互不混算。
  • 出口固定：网络出口在服务器侧，出口地址长期不变。

记账与隔离按实际结果验证，非仅配置声明。

常见问题

这和 API 中转站是一回事吗

不是。中转站转售的是按量计费的 API 额度；本方式的上游是服务器上的 Claude Max 订阅账号，提供的是一套配好的 Claude Code 环境。 计费时按官方 API 价折算，那只是把用量换算成可比较金额的口径。详见方式一首节。

是否需要自备 Claude 账号

方式一不需要。方式二需要，开通后账号归本人所有。

是否需要自备代理

方式一不需要，网络出口在服务器侧。方式二需要自备，或采用推荐方案。

能否使用网页版 claude.ai

方式一不可以，仅提供 Claude Code 命令行。需要网页版或桌面端请选择方式二。

代码是否会被上传

不会。方式一的 Claude Code 运行在本机，代码与文件始终在本机。 服务器只转发模型请求并记录 token 用量，对话内容不写入任何日志。

Windows 是否可用

可用。安装 WSL 后在 WSL 中执行安装命令。

额度用尽后如何处理

仅停止发送新请求。本机文件不受影响，充值后立即恢复，无需重装。

是否会改动本机原有的 Claude 配置

不会。客户端的配置与会话历史都在自己的目录内，本机原有的 claude 与 shell 配置不受影响，两边互不干扰。

如何开始
