Claude Max 拼车共享仅 Claude Code

在本机运行 Claude Code，账号与网络出口由服务器提供，多人共享，按用量计费。

本机无需 Claude 账号，无需代理，无需配置环境变量。 Claude Code 在本机执行，读写本机文件；仅模型请求经服务器转发。

使用方式

环境要求

系统所需环境
WindowsWSL（Ubuntu 即可）
macOS自带终端
Linux直接可用

另需 curl 与 Python 3.8 以上，多数系统已自带。

安装

curl -fsSL https://srv1890566.hstgr.cloud/install.sh | sh

执行后按提示粘贴 key。安装过程会检查本机的 Claude Code，未安装则自动安装， 已安装则检查更新。可重复执行。全程一至两分钟。

key 单独提供，一人一把，可按需签发多把并单独停用。

运行

sharedcc-claude

Claude Code 运行在本机，处理的是本机文件，本机的编辑器与终端照常使用。 参数原样转交给本机的 Claude Code，例如 sharedcc-claude --model opus。

常用命令

sharedcc-claude --quota     # 本周剩余份额与刷新时刻
sharedcc-claude --status    # 服务状态与版本
sharedcc-claude --update    # 更新到最新版本
sharedcc-claude --doctor    # 一键体检，输出诊断信息
sharedcc-claude --proxy URL # 经指定代理连接（默认直连；填 off 取消）
sharedcc-claude --help      # 全部命令

出现问题时运行 --doctor，把输出发给管理员即可。 输出只包含连接诊断信息，不含对话内容，key 以掩码显示。

会话与配置

配置与会话历史独立于本机原有的 claude，两边互不影响。 本工具的文件都在 ~/.sharedcc-claude/，不改动本机 ~/.claude 中的任何内容。

购买方式

按 usage 购买

购买的是账号周用量池的份额，单位是百分点。 1 点 = 该账号一周总产能的 1%。每周按所购份额发放，随账号的周窗口同步刷新。

档位按官方的档位比例折算：Max 20x 账号上，一份 Max 5x 当量为每周 25%。

usage 如何扣减

按每次请求实际消耗的 token 计算。四类 token —— 输入、输出、缓存写入、缓存读取 —— 各自乘一个系数后累加，折算为扣减的百分点。

系数由该账号的实测数据拟合得出，使扣减量与实际占用的产能成正比： 余额随用量线性下降，不会因为用法不同而突然变快或变慢。

每条请求的扣减独立记录，逐条可查，可随时索取本人的用量明细。 份额用尽仅停止发送新请求，本机文件不受影响。

sharedcc-claude --quota 随时显示本周剩余份额与刷新时刻。

为什么按 usage 而不按 API 额度计价

同样的用量，折算成"等效官方 API 额度"因人而异，主要取决于缓存命中率。

缓存读取在官方定价中按输入价的 10% 计费，但它几乎不占用账号的周产能。 因此缓存命中率越高的用法，同一份 usage 对应的等效 API 额度越高。 实测中这一差异约 40%：1 个百分点对应 $14 至 $20 的官方 API 额度， 高频复用长上下文的用法落在高端，每次都重新提交完整上下文的用法落在低端。

按美元额度报价，须按最不利的情况定价；按 usage 计价，则与用法无关 —— 买到的份额是确定的，不因缓存命中率高低而变动。

份额周期

份额随账号的周窗口刷新，每周重新发放。 未用完的部分不结转。

车队

人数确定后可组固定车队，单价与上述一致，份额按车队整体安排。 适用于同一课题组或同一项目共同使用。

需要账号不与他人共享的，见账号托管。

质保

三种服务中只有本方式提供质保，内容为两条：

  • 账号封禁风险由服务方承担：账号在服务方名下，风险不由使用者承担。
  • 不可用即退款：使用期内账号不可用的，按剩余余额退款。

订阅协助与账号托管均不含上述质保。

优势

代码不出本机

  • 文件始终在本机：Claude Code 在本机运行，读写的是本机文件，不会上传。
  • 本机不持有账号凭据：Claude 账号的凭据仅存在于服务器，使用者侧不接触。
  • 不改动本机配置：工具的文件都在自己的目录内，本机原有的 claude 与 shell 配置不受影响。

可用性由服务端维护

  • 一条命令装完：安装脚本会一并处理 Claude Code 的安装与更新，无需事先准备。
  • 直连：服务器有公网地址，客户端直接连接，无中间环节。
  • 出口固定：网络出口在服务器侧，地址长期不变，不随使用者所在网络变化。
  • 自更新：客户端启动时自动检查并更新，无需手动跟版本。

记账与隐私

  • 不保存对话内容：Claude Code 运行在本机，服务器只做两件事——转发模型请求、 记录用量。落到账目里的字段是固定的：时间、使用者、模型、状态、token 数、 请求参数（如 max_tokens）与客户端版本标识。 请求与回复的正文不写入任何日志，密钥也不记录。
  • 用量逐条记录：每次请求的模型与 token 消耗均有记录，账目可查、可核对。
  • 额度实时可见：--quota 显示剩余额度与失效时刻。
  • 按 key 归属：每次请求归属到本人的 key，账目互不混算。

用量明细可随时索取，逐条列出时间、模型与 token 数，与扣减的额度一一对应。
